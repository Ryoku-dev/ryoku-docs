There are three ways to run Ryoku with respect to CachyOS:

| Path | What you get | Where |
|---|---|---|
| **Ryoku on Arch** | The stock Arch `linux` kernel and the Arch userland | Arch ISO, or the script installer on Arch |
| **Ryoku on Arch plus the CachyOS layer** | The CachyOS kernel and tuning on top of the Arch userland, with the stock kernel kept as a boot fallback | The **CachyOS layer** question in the Arch ISO or script installer, or the **CachyOS Layer** bundle in Ryostore |
| **The CachyOS edition** | A full CachyOS system: CachyOS's pacman, its repositories for your CPU tier, `linux-cachyos` with the CachyOS LTS kernel as fallback | The CachyOS ISO, or the script installer on CachyOS |

This page is about the middle row: what the layer adds, how to get it, and how
to back out.

## What the CachyOS layer adds

- The `[cachyos-v3]` repository above `[core]`, trusted through the CachyOS
  signing key, and multilib for Proton's 32-bit libraries.
- `linux-cachyos` and `linux-cachyos-headers`: EEVDF with `sched-ext`, Clang
  ThinLTO and AutoFDO, the Cachy patchset, built for x86-64-v3.
- `cachyos-settings`: CachyOS's sysctl, udev, modprobe and systemd tuning.
- `scx-scheds`: the sched-ext userspace schedulers (bpfland, rusty, lavd).
- `ananicy-cpp` and `cachyos-ananicy-rules`: the auto-nice daemon that keeps
  the compositor and foreground apps responsive under load.
- `proton-cachyos-native`: the CachyOS Proton build for Steam and Lutris.

It does **not** add the baseline `[cachyos]` repository (CachyOS's forked
pacman) or the `cachyos-core-v3` and `cachyos-extra-v3` userland rebuilds, so a
later `pacman -Syu` cannot quietly replace your userland or your package
manager. Your desktop, defaults and the `[ryoku]` repository stay as they were.

<Warning>
The layer needs a CPU with **x86-64-v3** support (almost every CPU since about
2015). On a CPU without it, the installer skips the layer and says why.
</Warning>

## Get it at install time

The Arch ISO asks about the CachyOS layer after the Rashin question; the script
installer shows it as a toggle on plain Arch. Both are off by default.

- It needs a network connection, also on an offline ISO. The ISO only offers it
  while the network is up.
- The layer is added after the desktop is installed: the repository helpers
  run first, then one full-upgrade transaction installs the packages, so the
  whole system is current from the network.
- If the CachyOS mirror is unreachable or a step fails, the install carries on
  without the layer and tells you to add it later from Ryostore.
- The boot menu gets a CachyOS kernel entry next to the stock one.

## Add it later

Open Ryostore, find the **CachyOS Layer** bundle, and install all of it or pick
single items. It adds the same repositories and packages as the installer.
Reboot to run the new kernel; the stock kernel stays installed and bootable.

<Warning>
Installing a kernel rebuilds every DKMS module against it, so watch for NVIDIA
build errors during the transaction. `/boot` also gains a second kernel image
and initramfs.
</Warning>

## Should you switch?

<Tabs>
  <Tab title="Pros">
    - An optimized, patched kernel with `sched-ext`, so you can try a latency
      or gaming scheduler.
    - CachyOS's system tuning and the auto-nice rules, which keep a busy
      machine responsive.
    - CachyOS Proton for games.
  </Tab>
  <Tab title="Cons">
    - Kernel updates now depend on one more upstream being healthy.
    - Every DKMS module rebuilds against the new kernel; a failed rebuild means
      that module is missing on that kernel until it is fixed.
    - The CachyOS kernel tracks mainline more closely than Arch's `linux`.
  </Tab>
</Tabs>

The gain is real for gamers and heavy multitaskers; a light desktop will barely
notice it.

## Rollback

- **Boot the stock kernel.** The stock Arch kernel is never removed. Pick its
  entry in the Limine menu and you are back.
- **Recover the whole transaction.** Installing the layer is a pacman
  transaction, so snapper and snap-pac take a pre and post snapshot pair and
  limine-snapper-sync lists them in the boot menu. See [Updates](/docs/updates).
- **Remove it.** Remove the bundle's items in Ryostore. The `[cachyos-v3]`
  repository line stays in `/etc/pacman.conf`; it is inert with no CachyOS
  packages installed, so delete it by hand only if you want a clean file.

## Is it still Ryoku?

Yes. A distribution is defined by its desktop, tooling, repository and
defaults, not by the kernel it boots. With the layer the system stays Ryoku on
the Arch base, with the `[ryoku]` desktop, the `ryoku` CLI and the same
defaults. If you want CachyOS underneath, install the CachyOS edition instead.
