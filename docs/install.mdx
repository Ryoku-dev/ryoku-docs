---
title: Install Ryoku
description: Boot a signed Ryoku ISO for Arch, CachyOS or Void, answer the installer's questions, and reboot into the desktop.
---

Ryoku ships signed live ISOs for Arch, CachyOS and Void. Boot one, answer a
short series of questions in a terminal installer, and the backend lays the
base system, the Ryoku desktop and the apps you picked, and a Limine boot menu
onto the disk. There is no archinstall in the loop and no hidden JSON: plain
bash runs the stages in order, so you can read the whole thing top to bottom
and follow exactly what happens to the disk.

<Info>
Installing next to Windows on one disk? See [Dual-boot with
Windows](/docs/dual-boot); you make the free space first. Already running Arch,
CachyOS, Void or Fedora? [Convert your machine in place](/docs/convert)
instead of reinstalling.
</Info>

## 1. Get an ISO

Public ISO availability is tracked on [ryoku.dev](https://ryoku.dev). You can
also build the image yourself from the monorepo; see
[ISO build recipe](/docs/iso-build-recipe) for the full procedure and the
hardware notes.

A USB stick of at least 8 GB is fine. Flash the ISO with `dd`, balenaEtcher,
or Ventoy.

## 2. Verify the signature

Every release is signed by `Ryoku Releases <releases@ryoku.dev>`, fingerprint
`EB6D 3C0F 55A7 B3CA BA6B  2838 847B 274F 025D D6E3`. Always check the
imported key's fingerprint before trusting it. The public key lives in the repo
at
[`keys/ryoku-release-key.pub.asc`](https://github.com/Ryoku-dev/ryoku/blob/main/keys/ryoku-release-key.pub.asc).

```bash
# Import the release key
curl -sSL https://raw.githubusercontent.com/ryoku-dev/ryoku/main/keys/ryoku-release-key.pub.asc \
  | gpg --import

# Show the fingerprint and compare it against the one in the repo
gpg --fingerprint releases@ryoku.dev

# Verify the ISO against its detached signature
gpg --verify ryoku-<date>-x86_64.iso.sig ryoku-<date>-x86_64.iso
```

[Release pipeline](/docs/release-pipeline) has the full walkthrough of what
good output looks like and the offline-keyring path.

See [Verifying downloads](/docs/security) for the signing key, checksums, and
what a good check looks like. The same verification also guards the
[in-place converter](/docs/convert).

## 3. Try in a VM first (optional)

Ryoku targets modern desktops and laptops. If you want to walk through the
installer before committing to bare metal, boot the ISO in QEMU/KVM,
VirtualBox, or VMware with at least 16 GB RAM and a 60 GB virtual disk. For
first-class daily use on real hardware, target 32 GB RAM and 80 GB free disk.

## 4. Boot the installer

The ISO is a live image with one job: boot the machine and drop you straight
into the Ryoku installer.

<Steps>
  <Step title="Auto-login to the installer session">
    The live system logs in as root on `tty1` and starts a small Wayland kiosk
    (`cage`) running a terminal that runs `ryoku-tui`. The serial console and
    the other VTs stay plain root shells for headless or recovery use.
  </Step>
  <Step title="Answer the questions">
    `ryoku-tui` asks, in order: keyboard layout, system locale, time zone,
    network, hardware, hardware profile, graphics mode, window manager, web
    browser, login shell, file manager, Rashin, the CachyOS layer (Arch ISO
    only), Apps & tools, target disk, disk strategy, disk layout, hostname,
    primary user, password and disk encryption. Nothing is written to disk
    until you confirm on the Review screen, and each step can be revisited from
    the rail on the left.
  </Step>
  <Step title="Hand off to the backend">
    On confirm, the TUI exports your choices as `RYOKU_*` environment
    variables and runs `ryoku-install`. The same variables can be set by hand
    on the serial console for a headless install; `RYOKU_DRYRUN=1` runs every
    stage without touching the disk.
  </Step>
</Steps>

## 5. Choose what you install

The ISOs and the [script installer](/docs/convert) share one list of choices.
Whatever you leave out is recorded in `~/.local/state/ryoku/provisioned`, so
`ryoku update` and `ryoku doctor` never put it back.

| Question | Choices | Default |
| --- | --- | --- |
| Window manager | Hyprland, niri, Wayfire (experimental; Arch and CachyOS) | Hyprland (niri on Void) |
| Web browser | Firefox, Chromium, Zen (Arch and CachyOS), none | Firefox |
| Login shell | Fish, Zsh with Oh My Zsh, Bash with ble.sh | Fish |
| File manager | Files (Nautilus), Dolphin, Thunar | Nautilus, because Ryoku's stash menu lives in its right-click menu |
| Rashin | yes or no | yes |
| CachyOS layer | yes or no, Arch ISO only | no |
| Apps & tools | every optional app Ryoku ships | all on |

- **File manager.** The one you pick is installed, becomes the files role
  (the launcher's Files entry and "open folder" actions) and handles folders.
  You can change the role later in Ryoku Settings.
- **Rashin.** Ryoku's AI agent: Ask on `Alt + Space`, the Rashin window and
  the bar's AI usage. It runs the Hermes agent, which installs at your first
  login once the machine is online. Turn it off later on the **Rashin** page
  of Ryoku Settings. On Void the desktop package requires it, so the step only
  explains it.
- **CachyOS layer.** Adds the CachyOS repositories and kernel, with the Arch
  kernel kept as a boot fallback, plus system tuning, sched-ext schedulers,
  ananicy-cpp and CachyOS Proton. It needs a network connection, even on an
  offline ISO, and the install carries on without it when the CachyOS mirror
  is unreachable. It is the same set as the Ryostore **CachyOS Layer** bundle;
  see [Kernels](/docs/kernels).
- **Apps & tools.** The Ryoku apps come first: Ryotunes (music), Ryoport (VMs,
  SSH and serial consoles) and RyoManager (system monitor and task manager).
  Then the terminal tools (Starship, Fastfetch, Yazi, the modern CLI tools
  eza, bat, fzf and zoxide, the Git tools), media, gaming, system services and
  developer toolchains. Kitty, Neovim and btop are marked required because
  desktop features open them.

## 6. What the backend does

`ryoku-install` runs the stages below, each in its own file under
`installation/backend/lib/`. It streams its log to stdout and emits
`@@RYOKU_STEP <id>` sentinels so the TUI can draw staged progress; on success
it prints `@@RYOKU_DONE` and exits 0.

| Stage | What it does |
| --- | --- |
| `preflight` | Validate the `RYOKU_*` answers, require root, require UEFI on Arch and CachyOS (Void also installs on legacy BIOS), sanity-check the target disk. |
| `disk` | Partition the target per `RYOKU_DISK_STRATEGY` (`whole` to wipe, `alongside` to dual-boot), create the ESP and root partitions. |
| `luks` | Format and open the root partition as LUKS2, only when `RYOKU_ENCRYPT=1`. |
| `filesystem` | Make the filesystems and create the Btrfs subvolumes (`@`, `@home`, `@snapshots`, optional `@backups`), then mount them. |
| `pacstrap` | Install the base system, microcode and GPU drivers, minus the packages you left out. |
| `configure` | Locale, time zone, hostname, console keymap, the primary user with the login shell you picked, NetworkManager. |
| `deploy` | Add the signed `[ryoku]` repository, then install `ryoku-desktop`, the variant for your window manager, your file manager and the Ryoku apps and Rashin you kept. Seed the first-login notes: the Default rice, and the Hermes setup when Rashin was kept. Hide a deselected Ryoport for the new user. |
| `drivers` | Wire up the GPU profile (`amd-nvidia`, `amd`, `intel`, or `vm`) and any per-profile services. |
| `cachyos layer` | Arch ISO only, when chosen: add `[cachyos-v3]` and multilib, then one full upgrade that installs the kernel, tuning, schedulers and Proton. |
| `bootloader` | Install Limine with an entry per installed kernel and the Plymouth splash. |
| `aur` | Build and install the AUR set. |
| `snapshots` | Configure snapper, `snap-pac` and `limine-snapper-sync` so updates take pre and post snapshots and Limine lists them in the boot menu. |

The GPU and monitor helpers write the compositor's GPU and monitor files on
the first login, so the installer does not run them.

## 7. Reboot

When the backend finishes, reboot and remove the USB. The login screen appears;
log in with the user you created.

Continue with [First boot](/docs/first-boot) for what to expect on the desktop
and the first few keys worth pressing.

## Hardware notes

The shipped GPU profiles are `amd-nvidia` (hybrid laptop with NVIDIA + AMD),
`amd`, `intel`, and `vm`. Secure Boot is not configured automatically; the
[ISO build recipe](/docs/iso-build-recipe) tracks the working hardware list
and the harmless chroot warnings you can ignore.
