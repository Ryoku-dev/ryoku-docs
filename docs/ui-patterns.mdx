The Ryoku shell is **Quickshell (QML) under `ryoku/shell/quickshell/`, driven
by the `ryoku-shell` Go daemon under `ryoku/shell/ipc/`**. This page is the
short version of the contract for changing or adding UI. The full rules live
in the repository:
[`docs/ui-ux.md`](https://github.com/Ryoku-dev/ryoku/blob/main/docs/ui-ux.md),
[`docs/frame.md`](https://github.com/Ryoku-dev/ryoku/blob/main/docs/frame.md),
[`docs/structure.md`](https://github.com/Ryoku-dev/ryoku/blob/main/docs/structure.md)
and
[`docs/conventions.md`](https://github.com/Ryoku-dev/ryoku/blob/main/docs/conventions.md).

## View and logic stay apart

- **QML renders and animates.** Each surface is its own directory and each
  component is a single `.qml` file.
- **`ryoku-shell` decides.** The Go daemon supervises the shell, owns
  wallpaper, clipboard and lock state, registers as the GNOME keyring prompter,
  and serves the control socket.
- **Nothing names a compositor.** The shell reads the neutral window-manager
  singleton and asks capabilities; only `ryoku/wm/` knows Hyprland or niri.

QML never holds policy. When the UI needs a system change (packages, services,
displays, power, network, updates, wallpaper, hardware) it goes through
`ryoku-shell` or a named `ryoku-*` helper behind a narrow service.

## One shell, one component per file

Every surface runs in one `qs -c shell` process, drawn per monitor from one
scene (`shell/shell.qml`):

| Directory | What lives there |
| --- | --- |
| `shell/modules/` | One directory per surface: `bar` (the frame bars and the bar styles), `sidebar`, `dock`, `launcher`, `overview`, `wallpaper`, `visualizer`, `osd`, `notifications`, `capture`, `clipboard`, `desktop` and more. |
| `shell/services/` | The shared singletons every surface reads, including `Scheme` (colors) and `Motion`. |
| `shell/components/`, `shell/utils/` | Shared UI primitives and shared JS. |
| `ryoshot/`, `welcome/`, `stage/`, `keys/` | Capture and annotation, the first-run tour, the Stage Editor, and Kit. |
| `plugins/` | The third-party plugin runtime and the `Ryoku.PluginKit` module. |

Compose with components; do not merge unrelated UI into one file. A new concern
is a new `.qml` next to the surface it belongs to.

## Shared tokens

`Ryoku.Ui` (`ryoku/ui/`) is the module the shell, the Hub and the apps import
for one look. Its `Tokens` singleton carries the palette roles, type, geometry
and the app motion set; the shell resolves the same palette through
`shell/services/Scheme.qml`, with a thin local `Theme.qml` per surface that only
names the roles it uses.

- **Never write a hex, a font name, a radius or a duration in a component.**
  Read the token.
- **Two colors are fixed.** `Theme.brand` (`#e2342a`, the vermillion of the 力
  seal) and `Tokens.alert` (the same red). Everything else derives from the
  wallpaper.
- **The accent lives on the frame, not the content.** Depth is a hairline, not
  a shadow; a shadow appears only where something genuinely floats.

## Motion

Motion is short and purposeful: it explains a state change.

- **Apps and the Hub** use the `Tokens` set: `snap` (90ms), `move` (170ms),
  `swap` (210ms) and `flap` (110ms).
- **The shell** uses `Motion`'s named tokens (`barReveal`, `menuSlide`,
  `sidebarEnter`, `push`, `morph`, `spatial` and the rest). Every shell token is
  already scaled by the user's tempo and collapses to zero under reduce-motion,
  so read the token and never wrap it again.
- **The frame's give is physical.** `BlobRect` (in the `Ryoku.Blobs` plugin)
  solves an underdamped spring from its own velocity, which is the liquid feel
  when a popout grows out of the frame. A popup that emerges from the frame
  grows as the frame expanding, never as a separate panel sliding or fading in.

## Layout discipline

- Use stable `width`, `height` or `implicit*` sizing for repeated controls.
- Use the shared spacing tokens between rows and sections.
- Cards for repeated items, menus, modals and framed tools; avoid nested cards.
- Keep text inside controls short enough to fit at narrow widths.
- Do not use viewport-scaled font sizes.

## The dev loop

`ryoku/shell/dev-run.sh` launches the shell from the checkout with hot reload,
so QML edits show as you save. `dev-stop.sh` releases the dev shell. For changes
touching the daemon or a shared service, trace the flow from the config or IPC
into every consumer rather than patching one visible page.
