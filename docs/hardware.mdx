Ryoku profiles your hardware at install time and seeds the right defaults, then
hands you the controls in **Ryoku Settings** (the Hub), opened with `Mod+,`.
Displays, graphics and power, and input each have their own page. This page is
the map. For hand-editing the underlying files, see
[Customize](/docs/customize); for every page in full, see
[Settings](/docs/settings).

## Displays

**Ryoku Settings > Displays** is the display control panel. It lists every
connected output and lets you set, per output:

- Resolution and refresh rate
- Scale (fractional scaling for HiDPI panels)
- Rotation
- Position in the layout
- Mirror vs extend
- Named layout profiles you can switch between
- Night light: a warmer tint on demand, from sunset to sunrise, or between hours
  you choose

Applying a change writes the per-machine drop-in generated by `ryoku-monitor`
(`monitors.lua` on Hyprland, `monitors.kdl` on niri). Ryoku rewrites it on
hotplug or a GPU reset, and `ryoku update` never resets it.

<Warning>
  Laptop (eDP) panels expose only their **native resolution**. To get a smaller
  logical desktop, use the **scale** options instead of a lower resolution; they
  are labelled with the logical resolution they produce (for example 2048x1280)
  and are the Wayland-correct way to downscale. If `Apply` toasts a rejection,
  the compositor refused that mode or scale; pick one of the offered
  clean-divisor scales.
</Warning>

### Quick mirror / extend toggle

Press `Mod+P` to cycle the displays through internal only, external only and
both. Handy for plugging into a projector or a TV without opening Settings. See
[Keybindings](/docs/keybindings) for the full bind list.

### Hand-pinning a layout

When the page cannot express what a stubborn display needs (a fake-EDID monitor
that wants a forced mode or modeline, a precise position), pin it yourself in
`monitors_user.lua` (Hyprland) or `monitors_user.kdl` (niri). It loads after the
generated file, so your pins win, and it is never touched by updates. See
[Customize](/docs/customize).

## Graphics & Power

**Ryoku Settings > Graphics & Power** lists every detected GPU and pins the
primary render device through `ryoku-gpu`. On a hybrid laptop (a discrete NVIDIA
or Radeon beside the CPU's integrated GPU) the integrated GPU is the
battery-friendly default. Pick the discrete or external GPU there to render the
desktop on it instead. Heavy work such as video decoding goes to the strongest
GPU either way.

<Warning>
  The GPU pin is read once when the compositor starts, so a change takes effect
  on the **next login**. Log out and back in to apply it.
</Warning>

The page offers three host graphics modes:

| Mode | What it does |
| --- | --- |
| Hybrid | No pin; the integrated GPU renders the desktop (best battery). |
| Performance | Pins the strongest GPU (the discrete one) as the primary renderer. |
| Passthrough | Pins the integrated GPU alone, freeing the discrete GPU for a virtual machine. |

From a terminal, `ryoku-gpu` prints what it detected and what it chose:

```bash
ryoku-gpu           # detection plus the current pin and udev-rule state
ryoku-gpu detect    # just the detected GPUs (strongest first)
```

<Tip>
  To force the discrete GPU on a laptop against the battery-first default, run
  `RYOKU_GPU_FORCE=1 ryoku-gpu persist`. For a GPU that will not drive the
  desktop, see [Troubleshoot > The wrong GPU is being
  used](/docs/troubleshoot#the-wrong-gpu-is-being-used).
</Tip>

## Input

**Ryoku Settings > Input** covers keyboards and pointing devices:

- Keyboard layout (and variant)
- Key repeat rate and delay
- Mouse and touchpad behaviour (speed, natural scroll, tap-to-click, gestures)

The installer carries over the keyboard layout you chose, and the Input page is
where you change it later. Layout changes apply live; `ryoku keyboard apply`
carries the layout to the greeter, the console and the disk passphrase prompt
(see [The ryoku command](/docs/cli#one-layout-everywhere-ryoku-keyboard)).

## Power & idle

An idle session steps down in stages: the screen dims, the session locks, the
displays switch off, and finally the machine suspends. Each stage has its own
timing on battery and on AC, set on the **Graphics & Power** page alongside the
power profile and the battery charge limit. The same idle policy runs on every
window manager.

The session also locks before sleep or suspend, and restores brightness and the
displays on resume. Alongside it:

- **Battery** is read through `upower`; the shell surfaces charge and status.
- **Brightness** keys drive laptop backlights and external DDC monitors alike
  (`ryoku-cmd-brightness`).
- **Night light** lives on the **Displays** page and is remembered at your
  chosen color temperature.
