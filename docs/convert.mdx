title: Convert a machine you already have
description: Turn an existing Arch, CachyOS, Void or Fedora install into a Ryoku machine with one reversible command.

Already running Linux? You do not need the ISO. One command converts an
existing Arch, CachyOS, Void (glibc) or Fedora® 44/45 system into Ryoku in
place, and the same tool undoes it. Everything it touches is backed up first,
your desktops and files stay put, and Ryoku is layered on top rather than
installed over you. It never partitions a disk.

<Info>
Starting from a clean disk or a new machine instead? Boot the signed ISO; see
[Install Ryoku](/docs/install).
</Info>

<Warning>
The script installer rewrites your desktop configuration and is still being
tested across hardware and setups. Back up first, run the dry run, and prefer a
machine you can afford to reinstall.
</Warning>

## The one-liner

Run this as your **normal user**, not root. The script calls `sudo` only when it
needs elevation.

```bash
curl -fsSL https://raw.githubusercontent.com/ryoku-dev/ryoku/main/ryoku-shell-installer/install.sh | bash
```

`install.sh` is a small bootstrap: it detects the package manager (pacman,
XBPS, dnf, or apt for the Debian source build), checks for `x86_64`, downloads
the `ryoku-shell-install` binary, verifies its SHA256 against a committed
checksum, and hands it your terminal. Every real decision lives in that
interactive installer. See [Verifying downloads](/docs/security) for the
verification path.

## Choose what you install

The plan screen shows the same choices as the ISO installer:

- **Window manager**: Hyprland or niri (Void is niri only; Wayfire is
  experimental on Arch and CachyOS).
- **Web browser**: Firefox (recommended), Chromium, Zen on Arch and CachyOS, or
  none.
- **Login shell**: Fish (recommended), Zsh or Bash. A supported shell you
  already use is kept.
- **File manager**: Files (Nautilus, recommended because Ryoku's stash menu
  lives in its right-click menu), Dolphin or Thunar. One you already have is
  kept.
- **Rashin**: Ryoku's AI agent. It runs the Hermes agent, and the first login
  opens the Hermes setup unless Hermes is already installed. On Fedora and Void
  it is part of the desktop package.
- **Apps**: the Ryoku apps first (Ryotunes, Ryoport, RyoManager), then the
  terminal tools, media, gaming and service rows. Kitty, Neovim and btop are
  required because desktop features open them.
- **CachyOS kernel and tuning**: only on plain Arch. Off by default. After a
  mirror check it adds the CachyOS repositories and kernel (the Arch kernel
  stays as a fallback), system tuning, sched-ext schedulers, ananicy-cpp and
  CachyOS Proton. When the mirror is unreachable or the CPU lacks x86-64-v3 it
  says so and points at Ryostore instead of failing.

The developer toolchain (Go, Node.js, Python tools and mise) stays behind its
own **Developer toolchain** toggle here, off by default. Packages you leave out
are recorded in `~/.local/state/ryoku/provisioned` unless you already had them,
so `ryoku update` and `ryoku doctor` never add them later.

### Flags and variables

Pass options after `bash -s --`:

| Flag | Variable | What it does |
| --- | --- | --- |
| `--dry-run` | | Print every command it would run and change nothing. |
| `--yes` | | Run the plan with no prompts. |
| `--uninstall` | | Reverse a previous conversion (see [Reversible](#reversible)). |
| `--compositor <name>` | | Pick the window manager variant the host edition ships. |
| `--browser <id>` | `RYOKU_BROWSER` | `firefox`, `chromium`, `zen` or `none`. |
| `--shell <id>` | `RYOKU_LOGIN_SHELL` | `fish`, `zsh` or `bash`. |
| `--file-manager <id>` | `RYOKU_FILE_MANAGER` | `nautilus`, `dolphin` or `thunar`. |
| `--rashin=false` | `RYOKU_RASHIN=0` | Leave out Rashin. |
| `--without <ids>` | `RYOKU_WITHOUT` | Leave out apps by id, for example `ryotunes,ryoport`. |
| `--cachyos-layer` | `RYOKU_CACHYOS_LAYER=1` | Add the CachyOS layer (plain Arch only). |

For example, an unattended niri install with Dolphin and without Rashin,
Ryotunes and Ryoport:

```bash
curl -fsSL https://raw.githubusercontent.com/ryoku-dev/ryoku/main/ryoku-shell-installer/install.sh \
  | bash -s -- --yes --compositor niri --file-manager dolphin --rashin=false --without ryotunes,ryoport
```

A full dry run that touches nothing:

```bash
curl -fsSL https://raw.githubusercontent.com/ryoku-dev/ryoku/main/ryoku-shell-installer/install.sh \
  | bash -s -- --dry-run
```

To fetch the installer and its payload from a specific git ref instead of
`main`, set `RYOKU_SHELL_REF`. The ref also picks the package channel on Fedora
(`main` uses stable, `unstable-dev` uses testing):

```bash
curl -fsSL https://raw.githubusercontent.com/ryoku-dev/ryoku/main/ryoku-shell-installer/install.sh \
  | RYOKU_SHELL_REF=<ref> bash
```

<Warning>
Choices that are not available on the host edition are refused before `sudo`.
Zen and the AUR rows (LocalSend, Voxtype) are not available on Void or Fedora.
Fedora stays on the nouveau NVIDIA driver and refuses rpm-ostree editions. With
Secure Boot enforcing on Arch, the NVIDIA toggle is forced off (Arch kernels
reject unsigned DKMS modules); sign with `sbctl` or disable Secure Boot, then
run it again.
</Warning>

## What it does

The installer is a TUI in the ISO installer's visual language. It scans,
shows the plan, and writes nothing until you confirm.

<Steps>
  <Step title="Scan your machine">
    Detects your GPU and Secure Boot state, the display manager and network
    stack, installed desktops, rival Quickshell shells, known rices,
    conflicting user daemons, any plain Hyprland, niri or sway setup to migrate
    from, an Omarchy install to retire, your keyboard and monitor layout, and
    an interrupted previous run to resume.
  </Step>
  <Step title="Review the plan">
    The choices above, then the migration toggles: NVIDIA drivers, switch the
    login screen to SDDM with the Ryoku greeter, NetworkManager, remove rival
    shells, disable conflicting daemons, retire an Omarchy repo, carry over
    your monitor layout, AUR extras and the developer toolchain.
  </Step>
  <Step title="Back up everything it will touch">
    Before the first change, every config the plan touches is copied to
    `~/.local/state/ryoku/shell-install/backup-<timestamp>/` with a generated
    `restore.sh`. The script grows a line per saved item, so a kill at any
    moment still leaves a script that undoes what happened so far.
  </Step>
  <Step title="Add the signed repository and install">
    Trusts the signed Ryoku repository for the host (pacman, XBPS or RPM),
    installs the desktop, your window manager variant, your file manager, the
    Ryoku apps and Rashin you kept, and on plain Arch the CachyOS layer when
    you asked for it. Then it wires up SDDM, the greeter and NetworkManager.
  </Step>
  <Step title="Materialize and self-check">
    Lays down `~/.config`, sets the browser and files roles, hides a
    deselected Ryoport, leaves the first-login notes, runs `ryoku doctor` and
    verifies. Interrupted? Run it again: completed steps are recorded in
    `~/.local/state/ryoku/shell-install-state.json`, so it resumes where it
    stopped.
  </Step>
</Steps>

When it finishes, reboot into the Ryoku login screen. From there it is an
ordinary Ryoku machine: `ryoku update` keeps it current and `ryoku doctor`
heals it. Continue with [First boot](/docs/first-boot).

## Reversible

The conversion can be undone. Run the one-liner again with `--uninstall`:

```bash
curl -fsSL https://raw.githubusercontent.com/ryoku-dev/ryoku/main/ryoku-shell-installer/install.sh \
  | bash -s -- --uninstall
```

<Note>
If the `ryoku-shell-install` binary is still on your `PATH`,
`ryoku-shell-install --uninstall` does the same thing. The bootstrap above
always works because it fetches the installer again.
</Note>

Uninstall walks the conversion backwards:

1. Removes the Ryoku packages in one transaction (`ryoku-desktop` depends on
   the rest, so the package manager orders the removal).
2. Drops the Ryoku repository, keeping the original configuration beside it.
3. Walks the backup chain **newest to oldest**, running each `restore.sh` with
   a confirmation prompt, which puts every saved config back and re-enables
   the services and display manager it disabled. Decline one and the walk
   stops there, because the chain only makes sense in order.

Session packages (SDDM, PipeWire, NetworkManager and so on) stay installed:
they may predate Ryoku, and removing them can lock you out of a login. Your
backup directories are kept too; delete them once you are sure.

<Tip>
To roll back only the most recent conversion, run that run's own restore
script: `bash ~/.local/state/ryoku/shell-install/backup-<timestamp>/restore.sh`.
</Tip>

## What is touched and what is left alone

| Left alone | Changed only with your toggle |
| --- | --- |
| Desktop environments (GNOME, KDE, Cinnamon, Xfce) stay installed and selectable at the login screen | Rival Quickshell shells are uninstalled |
| niri and sway stay installed as fallback sessions | Conflicting daemons are disabled, never uninstalled |
| Your files and personal data | The old display manager is disabled, not removed, in favour of SDDM |
| Software you already had, even if you leave it out of the plan | The Ryoku repository and keyring are added, and dropped again on uninstall |

Every config the installer touches is copied, never deleted. Originals of
system files are kept as `*.pre-ryoku`, and per-run copies live in the backup
directory with their `restore.sh`. Your monitor layout and keyboard are carried
over from your existing setup so your screens and keys come back the way you
had them.
