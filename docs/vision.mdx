## Name

Ryoku (力, *chikara* or *ryoku*) is Japanese for "power" or "strength". The
project takes the name plainly: it is about power, and about making that power
beautiful.

## Tagline

**力と美のために** : *For the sake of power and beauty.*

Keep this line. It is the heart of the project.

## What it is

Ryoku is a hand-built Linux desktop for powerful desktops and laptops. One
shell, a [Quickshell](https://quickshell.outfoxxed.me) UI driven by a Go daemon
(`ryoku-shell`), runs on [Hyprland](https://hypr.land/) or
[niri](https://github.com/YaLTeR/niri), on Arch Linux, CachyOS, Void Linux and
Fedora. Every edition installs the same desktop as signed native packages, and
one repository holds the desktop, the installers and the system definition.

The base is deliberately lean and scales up with the apps, plugins and bundles
you actually use. Colors follow the wallpaper, the brand stays constant, and
one control plane (the `ryoku` command and Ryoku Settings) owns updates,
snapshots, appearance, displays and the shell.

## Who it is for

- Desktop and laptop users who want a tiling desktop that feels finished on
  strong hardware.
- Developers who need terminals, browsers, files, notes, containers and media
  tools ready on day one, without building the whole desktop from scratch.
- Power users who like a riced desktop but want the rice maintained as a
  product, not a private dotfiles pile.
- Users who want advanced workflows surfaced as plugins and bundles instead of
  tray icons and one-off scripts.

## What distinguishes it

- **A finished desktop on more than one window manager.** The default look is a
  product choice, not a placeholder, and it is the same on Hyprland and niri.
  Each window manager's config is written in its own language (Lua for
  Hyprland, KDL for niri), one concern per file.
- **One shell stack.** A single Quickshell UI plus the `ryoku-shell` daemon
  decide together (the daemon owns state, the UI renders), instead of stitching
  a dozen widgets and tray apps.
- **An installer that asks.** Browser, file manager, terminal tools, Ryoku's
  own apps and Rashin are choices on every install path, and what you leave out
  stays out.
- **Signed packages and one update command.** `ryoku update` brings Ryoku's
  packages current from its signed repository, re-lays the base config, runs
  `ryoku doctor`, and wraps the run in snapshots where the edition supports
  them.
- **A visual system.** Boot, login, lock, shell, terminal and app defaults are
  treated as one thing, anchored by the vermillion 力 seal.

## What it is not

- A fixed image you cannot shape.
- A bare window-manager starter kit with no defaults or direction.
- A wallpaper and a theme on top of someone else's desktop.
- A re-skin of an upstream shell. Upstream projects are important sources, but
  Ryoku's job is to turn the useful pieces into a Ryoku-owned, modular system.
  See [Omarchy heritage](/docs/omarchy-heritage) for what Ryoku adapts and what
  it owns outright.
